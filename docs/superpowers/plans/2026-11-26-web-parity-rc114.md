# Web parity RC114 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Port Android 2.91.12 to 2.91.14 features (contests, contribute page, local reminder, mushaf pieces) to the pure-JS web app without touching the database, workflow or main.

**Architecture:** Pure logic lives in ES modules (`.mjs`, node-testable) imported by `main.js` and exposed on `window`; UI lives in classic boot scripts that register pages through `RC50.page` (the existing page registry), reusing `RC50.sheet`, `RC50.seg`, `RC50.card`, `RC50.rpc`. All data goes through the existing RPCs.

**Tech Stack:** Vanilla JS, Vite, node --test, Playwright (system Chrome) with mocked `db.rpc`.

**Spec:** the task brief (contests, contribute, reminder, mushaf, misc) and the Android sources `ContestRules.kt`, `ContestsScreens.kt`, `ContributeScreen.kt`, `ReminderPanel.kt`, `reminders/*.kt`.

## Global Constraints

- No DB / RLS / role-permission change. RPC names and argument names exactly as in migrations 20261125/20261126.
- Arabic UI text, RTL, Cairo; no new animation (reduced-motion safe by default).
- Contribute page only for roles guardian, teacher, supervisor, admin. Not for observer (donor) or student.
- Reminder is local only (localStorage) and in-app; never claim background notification with the browser closed.
- Do not edit `.github/workflows`, do not merge to main, do not publish.

## Review Focus

- Dates typed with Arabic-Indic digits or RTL marks must parse (test in rules).
- A reminder whose time passed while the app was closed must show once on open, not repeatedly (test `dueOccurrence`).
- Guardian must never see reward-request section inside "تكفّل بحلقة" (browser test).
- Admin approving a contest with no halaqa must be blocked client-side (test `decisionError`).
- Halaqa picker must come from the server on every form open (browser test counts the rpc calls).
