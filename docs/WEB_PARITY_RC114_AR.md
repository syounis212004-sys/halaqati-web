# مواءمة الويب مع أندرويد 2.91.12 إلى 2.91.14 (RC114)

الفرع: `feature/web-parity-rc114`. لم يُدمج في `main` ولم يُنشر. لا تغيير في قاعدة البيانات ولا RLS ولا الصلاحيات ولا workflow النشر. كل الاستدعاءات دوال RPC مطبَّقة أصلًا (ترحيلان 20261125 و20261126).

## ما نُقل

### 1) المسابقات (`features/contests/`)
- `rules.mjs`: منطق نقي مطابق لـ `ContestRules.kt` (الحدود 3/80 و3/120 و10/2000 و3/500 وسبب الرفض 3/500، التواريخ يوم-شهر-سنة أو سنة-شهر-يوم بأرقام عربية وفارسية وإهمال علامات الاتجاه، السنة 2000..2100، النهاية ≥ البداية، التحويل إلى ISO قبل الإرسال، قرار الاعتماد/الرفض، حالة منتقي الحلقة).
- `ui.js`: صفحة `contests` عبر سجل الصفحات `RC50.page`:
  - المانح: «مسابقاتي» مع حالة (بانتظار/معتمدة/مرفوضة) وسبب الرفض ومرشح حالات، وإنشاء مسابقة (يُرسل دون حلقة إن لم يكن مربوطًا، ويحددها المدير).
  - المحفّظ والمشرف: تبويبان «مسابقاتي» و«مسابقات حلقاتي».
  - مدير النظام: قائمة المسابقات (الافتراضي: بانتظار القرار)، إنشاء (تُعتمد فورًا)، اعتماد برفع الحلقة وخيار «ربط المانح» (للمانح فقط)، رفض بسبب إلزامي. الاعتماد دون حلقة محجوب في الواجهة.
  - ولي الأمر: المعتمدة للقراءة فقط.
  - قوائم الحلقات (`contest_donor_halaqas`) والمسابقات تُقرأ من الخادم عند كل فتح، بلا تخزين مؤقت.
  - حقل التاريخ: كتابة حرة مع زر «تقويم» يستعمل `input type=date` ويكتب الناتج بصيغة يوم-شهر-سنة؛ الأخطاء تظهر تحت الحقل مع `aria-invalid`.
  - المانح يرى إدخالًا جديدًا «المسابقات» في القائمة الجانبية فقط.

### 2) صفحة «المساهمة» (`features/contribute/ui.js`)
- لأربعة أدوار فقط: ولي الأمر والمحفّظ والمشرف والمدير. لا تظهر للمانح ولا للطالب، ولا تغيير على صلاحيات `core/navigation.js` (إضافة عنصر قائمة فقط).
- ولي الأمر: «تكفّل بحلقة» (واجهة كفالة المانح نفسها بعد استخراجها كدالة `RC50.pledgesHtml` في `rc50/donor.js`، والبطاقات من `rc49_support_cards` فتحددها الخادم لحلقات أبنائه فقط، مع التعهد وكفالاتي وإثبات التحويل ومحادثة المدير دون تبويب طلبات المكافآت الخاص بالمانح)، «المسابقات» (قراءة)، «التذكير».
- المحفّظ والمشرف والمدير: «المسابقات» (ملخص حالة + زر الفتح) و«التذكير».

### 3) التذكير المحلي (`features/reminders/`)
- `schedule.mjs`: حساب الموعد التالي والموعد المستحق وحفظ التفضيلات في `localStorage` (مفتاح `halaqati_reminder_v1`)؛ الافتراضي الخميس 18:00 مفعّل؛ نصوص الأدوار كما في أندرويد.
- `ui.js`: لوحة (مفتاح، أيام، وقت، التذكير القادم، إرسال تجريبي)، لافتة داخل التطبيق عند الفتح بعد الموعد ومؤقت كل دقيقة أثناء الفتح، إشعار المتصفح عند الإذن الصريح، وبطاقة في الإعدادات لإطفائه.
- **حد الويب**: لا جدولة موثوقة والمتصفح مغلق. الواجهة تقول ذلك صراحة. الموعد الفائت يظهر مرة واحدة إن فُتح التطبيق خلال 24 ساعة (في أندرويد ساعتان)، وبعدها يُتجاوز.

### 4) المصحف (جزئي)
نُقل إلى المصحف التفاعلي الحالي (`native/mushaf.js` و`native/mushaf-jump.mjs`):
- نافذة «الانتقال» بتبويبات الصفحة والسور والأجزاء، وبطاقة «ضمن المقرر» (أول/آخر المقرر أو رقاقة لكل صفحة حتى 12)، وبحث السورة، والانتقال إلى آية (عبر جدول `HALAQATI_QURAN_LAYOUT` الموجود)، وجدول بدايات الأجزاء (اختبار يقارنه بتخطيط الصفحات المشحون).
- علامات مرجعية بالصفحة في `localStorage` (زر «☆ علامة» وقائمتها داخل النافذة). لا تلمس علامات الأخطاء التي تبقى في ذاكرة الجلسة فقط.

## ما لم يُنقل وأسبابه

| محرك DigitalKhatt | انظر التقييم أدناه | قرار قانوني ثم PR مستقل |
| زوم بإصبعين/عجلة | مصحف الويب أداة تعليم: لمسة وضغط مطوّل وسحب تظليل على الكلمات (`pointer events`). الزوم بإصبعين يتعارض مع السحب ويحتاج اختبارًا على أجهزة لمس فعلية؛ المتصفح يوفّر زوم الصفحة أصلًا | تصميم بوضع «تحريك/تكبير» منفصل |
| حركة تقليب الصفحات | لم تُضَف أي حركة. الإضافة تلزمها مهارة الحركة واختبار تخفيف الحركة، وقد تتعارض مع `fit()` والتحميل غير المتزامن للخط | بعد ثبات الزوم |
| الشريط العلوي الجديد | الصف الحالي (سابقة/تالية/رقم/إلى المقرر) باقٍ ويحتوي الآن الانتقال والعلامة | — |
| المنتقي المخصص للتاريخ | استُعمل `input type=date` الأصلي؛ في Safari القديم (قبل 16) قد لا يفتح، والكتابة تعمل دائمًا | — |
| الإصلاحات الأخرى (بند 5) | قوائم المسابقات والحلقات تُقرأ طازجة عند الفتح (منفّذ). لم أجد مقابلًا آخر في الويب بعد القياس | — |

### تقييم DigitalKhatt للويب
- في أندرويد الحزمة تُولَّد وقت البناء (`scripts/dk/make_dk_assets.py` من `madina.json` مثبّت) وتحوي مجاري الرموز التي تُرمّز نص القرآن، فلا تُرفع إلى المستودع. الرسم يتبع `precomputed/layout.ts` (MIT) ومخططات خط Madina (OFL).
- في الويب الحزمة (~5MB) لن تُحفظ في المستودع، فتلزم خطوة بناء إضافية في workflow النشر (تنزيل `madina.json` المثبّت وتشغيل بايثون) ثم استضافتها عامة على GitHub Pages، وهذا يجعل نص القرآن منشورًا كأصل عام بترخيص «غير محسوم قانونيًا». لذلك **لم أغيّر workflow النشر ولا أدّعي النقل**.
- الجدوى التقنية متوسطة: إعادة كتابة `DkRender` (~250 سطرًا) على Canvas2D/SVG، وتخزين الحزمة في Cache API، وربط معرّفات الكلمات (`ids.bin`: سورة:آية:موضع) بمعرّفات `HalaqatiMushafState` الموجودة، وحفظ الرجوع إلى QCF V2 مفتاحًا للميزة.
- الخطة: (1) قرار المالك في الترخيص والنشر العام؛ (2) PR مستقل يضيف خطوة البناء والتحقق (`verify_pack.py`) دون ربطها بالنشر؛ (3) مصحف DK خلف مفتاح ميزة؛ (4) اختبارات مطابقة المعرّفات للصفحات الـ604 كما فُعل مع QCF.

## الاختبار
- وحدات: `npm run check:rc114` (46 اختبارًا: قواعد المسابقات، جدول التذكير بحالات `ReminderScheduleTest` ومناطق زمنية مختلفة، منطق الانتقال، حواجز ثابتة: ترتيب الإقلاع وقائمة RPC المسموحة وعدم لمس الجداول وعدم إضافة حركة).
- متصفح: `npm run build && AXE_JS=<axe.min.js> node scripts/rc114-browser.mjs` (Chrome، `db.rpc` مزيّف، شبكة خارجية محجوبة، بيانات وهمية): أدوار ولي الأمر والمحفّظ والمشرف والمدير والمانح، العرض 360/390/768/1024/1440، الوضع الفاتح والداكن، RTL، لوحة مفاتيح بارتفاع 380، تخفيف الحركة، axe (wcag2a/aa/21aa)، ولقطات.
- حالة الأساس قبل التعديل: `check:parity` فيها 7 إخفاقات سابقة، و`check:regression` تفشل بـ«Version mismatch»، و`check:v2200` تفشل بخطأ تحميل؛ كلها قائمة قبل أي تعديل ولم تتغير. وأثناء ذلك لاحظت أن ملف `boot-script-order.json` كان متقادمًا (ينقصه 3 سكربتات) فحُدّث ليطابق `main.js`.
