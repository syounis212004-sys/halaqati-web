# حلقتي v2.14.0 — Offline-First Sync Engine

هذه النسخة مبنية فوق v2.13.9 المستقرة، وهدفها الوحيد تقوية العمل دون إنترنت والمزامنة. لم يتم تغيير محرك PDF أو تقارير العربية أو إدارة الطلاب أو صلاحيات Supabase.

## ما الذي تغير؟

- أضيفت قاعدة محلية حقيقية باستخدام IndexedDB داخل WebView/المتصفح.
- يوجد Outbox دائم لكل حساب، مع حالات: pending / syncing / failed.
- بقي localStorage كنسخة أمان ومصدر ترحيل للبيانات المعلقة من الإصدارات السابقة.
- عند أول تشغيل v2.14 يتم ترحيل طابور v2.13.x والنسخة المحلية القديمة إلى IndexedDB تلقائياً.
- كل جلسة جديدة تُعطى UUID ثابتاً على الجهاز قبل رفعها، لذلك إعادة المحاولة لا تنشئ جلسة مكررة.
- الحضور والغياب والتأخر والسلوك والحفظ والمراجعة والسرد تحفظ محلياً أولاً حتى عند وجود الإنترنت، ثم تبدأ المزامنة في الخلفية.
- تسميعات Offline تحصل على UUID ثابت، وتُرفع بـ upsert على id لمنع التكرار إذا نجحت العملية على الخادم ثم انقطع الرد.
- الحضور والسلوك يستخدمان upsert على (session_id, student_id).
- ترتيب المزامنة: إنشاء الجلسات أولاً، ثم طلبات حذف الجلسات، ثم البيانات التابعة.
- فشل سجل بيانات واحد لا يوقف بقية السجلات المستقلة. بعد 3 محاولات يبقى Failed ويظهر في شاشة حالة المزامنة.
- أخطاء الشبكة أو انتهاء جلسة الحساب توقف المزامنة بأمان بدون حذف الطابور.
- حذف جلسة أثناء Offline يحذف البيانات التابعة محلياً، وإذا كانت الجلسة موجودة على الخادم يضيف Tombstone لحذفها تلقائياً عند عودة الإنترنت.
- زر حالة الاتصال يفتح شاشة «حالة المزامنة» مع عدد العمليات والفاشل وإعادة المحاولة.
- الإعدادات تعرض بطاقة خاصة بالمزامنة دون إنترنت.

## حماية البيانات

1. IndexedDB هو التخزين المحلي الأساسي.
2. localStorage يبقى Mirror احتياطياً حتى لو تعذر IndexedDB في جهاز قديم.
3. بعد كل تعديل يتم تحديث Snapshot المحلي وOutbox.
4. أثناء المزامنة يتم حفظ حالة الطابور بعد كل عملية، لذلك إغلاق التطبيق في منتصف الرفع لا يعيد العملية من الصفر بصورة عمياء.
5. عمليات التسميع والجلسات الجديدة تستخدم UUID ثابتاً لمنع التكرار عند إعادة الإرسال.

## ما لم يتم تغييره

- `src/features/reports/runtime.js` مطابق للنسخة v2.13.9 المستقرة.
- محرك PDF: 300 DPI + Arabic-safe raster + searchable Unicode layer كما هو.
- `src/features/students/runtime.js` لم يتغير.
- حذف الحلقات، ربط ولي الأمر، اسم الحساب، وفتح الجلسة من الرئيسية بقيت كما كانت.

## الاختبارات المضافة

- `OFFLINE_V214_CHECK_PASS`
- `OFFLINE_V214_MODEL_SMOKE_PASS`: نموذج 500 عملية Offline + dedupe + failure isolation + tombstone.
- `IndexedDB offline outbox 500-operation smoke test` داخل GitHub Actions باستخدام متصفح حقيقي.
- كل فحوص PDF والعربية والـModules والـRegression القديمة ما زالت تعمل.

## اختبار الهاتف المقترح قبل النشر

1. ثبّت APK فوق النسخة الحالية بدون حذف بيانات التطبيق.
2. افتح جلسة والإنترنت مقطوع.
3. سجل حضور/غياب وسلوك وتسميع لعدة طلاب.
4. أغلق التطبيق بالكامل وافتحه مرة أخرى وهو Offline وتأكد أن البيانات ما زالت موجودة.
5. شغّل الإنترنت وانتظر المزامنة التلقائية.
6. افتح «حالة المزامنة» وتأكد أن العدد يصل إلى صفر.
7. جرّب إنشاء جلسة Offline ثم حذفها قبل تشغيل الإنترنت؛ يجب ألا تظهر على الخادم.
8. جرّب حذف جلسة موجودة على الخادم أثناء Offline؛ يجب أن تختفي من الجهاز ثم يُؤكد حذفها عند عودة الإنترنت.

## ملاحظة البناء

البيئة المحلية التي تم تجهيز الملفات فيها لم تستطع إكمال `npm install` بسبب مهلة تنزيل الحزم. لذلك اختبار Vite/Android الكامل وم smoke test الخاص بـ IndexedDB موضوعان داخل GitHub Actions ويجب أن يكون الـAction أخضر بالكامل قبل اعتماد APK.
