# Halaqati v2.40.3 - Vector PDF / Chromium

هذا الإصدار يستبدل مسار PDF النقطي (html2canvas + jsPDF + DPI) بمسار PDF متجهي حقيقي.

## Android
- قالب التقرير يبقى HTML/CSS ويستخدم Cairo وRTL الطبيعيين.
- إضافة Capacitor محلية باسم `HalaqatiPdf` تنشئ WebView مخصصًا خارج الشاشة.
- `WebView.createPrintDocumentAdapter()` يحول محتوى WebView إلى PDF stream.
- الناتج يحفظ مباشرة في Downloads/Halaqati على Android 10+.
- لا يوجد Canvas عملاق، لا 300 DPI، لا تقطيع صور، ولا طبقة نص مخفية.
- انتظار `document.fonts.ready` والصور قبل الكتابة مع مهلة تمنع التعليق اللانهائي.

## Web / PWA
- نفس قالب HTML/CSS يستخدم `window.print()` داخل iframe مخصص.
- يختار المستخدم "حفظ بتنسيق PDF" من نافذة Chromium.
- لا يمكن لمتصفح الويب تنزيل PDF متجهي بصمت بدون واجهة الطباعة لأسباب أمنية.

## خصائص PDF المحفوظة
- Cairo.
- اتجاه RTL سليم وتشبيك عربي من محرك Chromium.
- نص حقيقي قابل للتحديد والنسخ والبحث.
- أرقام إنجليزية 0-9.
- A4 رأسي أو أفقي.
- تعديل النص من المعاينة قبل التصدير.
- تغيير الخط والحجم ولون النص ولون العناوين.
- Auto-fit للجداول مع بقاء اسم الطالب في سطر واحد.
- رؤوس الجداول تتكرر عند انقسام الجدول عبر الصفحات.
- منع تقسيم الصف قدر الإمكان عبر CSS `break-inside: avoid`.
- صور الطلاب - إن وجدت - تبقى صورًا داخل PDF، بينما النص والجداول والأشكال CSS متجهية.

## تقرير ولي الأمر
PDF ولي الأمر يستخدم المحرك المتجهي نفسه. مسار JPG/الصورة لم يتغير.

## التوافق
لا يوجد SQL أو Migration لهذا الإصدار. Live Halaqa وV5 والخطط والمزامنة والإشعارات والـUpdater والـDeepLink محفوظة.

## ثبات وأمان مسار Android
- الـWebView الخاص بالطباعة يستخدم Activity Context منفصلًا عن واجهة التطبيق، ويُدمّر بعد انتهاء المهمة.
- توجد حماية terminal لمنع سباق المهلة الزمنية مع callbacks من إنهاء نفس مهمة PDF مرتين.
- توجد مهلات مستقلة للتجهيز والكتابة والحفظ، فلا تعود شاشة التقدم إلى دورة لا نهائية.
- HTML المأخوذ من المعاينة القابلة للتحرير يُنظف من script/iframe/object/embed/form وخصائص الأحداث قبل تمريره إلى WebView الخاص بالطباعة.
- أزيلت من runtime نفسه شيفرة 300-DPI والطبقة النصية المخفية القديمة؛ لم تعد مجرد مسار غير مستخدم.
