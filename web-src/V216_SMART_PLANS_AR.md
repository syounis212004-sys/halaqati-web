# حلقتي v2.16.0 — الخطط الذكية للحفظ والمراجعة

هذه النسخة تضيف محرك الخطط الذكية مع الحفاظ على مسارات PDF العربي، المزامنة الحالية، وإشعارات Capacitor الرسمية كما كانت في v2.15.7.

## ما أضيف

- خطة منفصلة لكل طالب أو خطة جماعية للحلقة مع تخصيص طالب بعينه.
- أنواع الخطط: حفظ، مراجعة، سرد، وتثبيت.
- نطاق قرآني دقيق بالصفحات أو الأجزاء أو الأرباع أو السور أو الآيات، اعتمادًا على بيانات مصحف حفص ذات 604 صفحات.
- توزيع تلقائي على أيام الدوام، ويوم استدراك اختياري بلا حفظ جديد.
- سقف تعويض افتراضي 150% من الورد الأصلي، وتمديد تلقائي لتاريخ النهاية عند تعذر امتصاص العجز بأمان.
- احتساب الإنجاز من `recitation_entries` الفعلية، وليس من عداد إجمالي قابل للتعارض.
- شرط جودة افتراضي «جيد جدًا»؛ تقييم «إعادة/ضعيف» يوقف الحفظ الجديد ويُنشئ تثبيتًا إجباريًا.
- مراجعة قريبة لآخر المحفوظ ومراجعة بعيدة دورية للمحفوظ القديم.
- اختبار مرحلي عند نهاية الحزب أو الجزء، مع اعتماد المحفّظ قبل فتح المقرر التالي.
- زر «تسميع المقرر اليومي» لتعبئة الصفحات ونوع النشاط داخل الجلسة بضغطة واحدة.
- لوحة الطالب وولي الأمر: هدف الشهر، الإنجاز، المتبقي، النسبة، حالة الخطة، ومقرر اليوم والأسبوع.
- لوحة المشرف: أفضل التزام، الطلاب المتأخرون، إنجاز الحلقات، والمخطط مقابل المنجز.
- تنبيه التأخر والتحضير المنزلي عبر نفس نظام الإشعارات الداخلي وPush المستقر.
- تخزين الخطة والأحداث والإنجازات محليًا، ثم مزامنتها عبر طابور v2.14 الحالي.

## ترقية قاعدة البيانات

طبّق الملف التالي على مشروع Supabase قبل فتح صفحة الخطط في الإنتاج:

```text
supabase/migrations/20260830144555_smart_plans_v216.sql
```

الترحيل ينشئ:

- `public.smart_plans`: تعريفات الخطط فقط.
- `public.smart_plan_events`: أحداث مستقلة قابلة للمزامنة مثل اعتماد الاختبار والتمديد التلقائي.
- فهارس للحلقة والطالب والخطة النشطة والأحداث المرحلية.
- RLS صريح للمسؤول والمشرف والمحفظ وولي الأمر، مع منع وصول `anon`.

يمكن تطبيقه عبر Supabase CLI:

```bash
supabase db push
```

أو نسخ محتوى ملف الترحيل إلى SQL Editor وتشغيله مرة واحدة.

> الخطط الشهرية القديمة في `student_goals` لا تُحذف. لا تُحوّل تلقائيًا لأن الخطة الذكية تحتاج نطاقًا قرآنيًا حقيقيًا، ويمكن إنشاء البديل الدقيق من واجهة «الخطط الذكية».

## البناء والاختبار

```bash
npm install
npm run check:smart-plans
npm run check:legacy
npm run build
```

اختبار الخطط يغطي:

- حدود الصفحات والأرباع والآيات.
- سقف التعويض والتمديد التلقائي.
- شرط الجودة والتثبيت الإجباري.
- اختبار نهاية الجزء واعتماده.
- أولوية تخصيص الطالب على الخطة الجماعية.
- المراجعة القريبة والبعيدة.
- يوم الاستدراك ومؤشر صحة الخطة.
- ثبات ملفات PDF وPush وEdge Function مقارنةً بـv2.15.7.

## نشر Web وAPK Update

استخدم ملف GitHub Actions:

```text
build-halaqati-v2.16.0.yml
```

واسم ملف المصدر المتوقع في مستودع البناء:

```text
Halaqati_Vite_Capacitor_v2_16_0_SMART_PLANS.zip
```

ينتج المسار نفسه:

- Web build.
- APK موقّع عند توفر أسرار التوقيع.
- `Halaqati-latest.apk` و`version.json` لحزمة التحديث.

إعداد Firebase و`halaqati-notify` لا يحتاجان تعديلًا خاصًا بهذه النسخة؛ تنبيهات الخطط تستخدم مسار `event_student` الحالي بمفتاح مصدر فريد لمنع التكرار.

## حدود الاستقرار

لم تُعدّل ملفات النظام التالية وظيفيًا:

- `src/features/reports/runtime.js`
- `src/features/reports/lazy.js`
- `src/features/notifications/runtime.js`
- `src/features/notifications/push-bridge.js`
- `supabase/functions/halaqati-notify/index.ts`

التغيير الوحيد داخل تسجيل التسميع هو إضافة معرف الخطة ونوعها وتاريخها إلى `selection_data` حتى يتتبع محرك الخطط السجل الصحيح دون تغيير الحفظ أو المزامنة الأساسية.
