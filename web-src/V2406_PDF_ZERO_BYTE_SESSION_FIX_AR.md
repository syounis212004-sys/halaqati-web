# حلقتي v2.40.6 — إصلاح PDF بحجم 0 بايت + الرجوع للحساب بعد الطباعة

## المشكلة التي يعالجها هذا الإصدار
في v2.40.5 أصبحت معاينة Android تعرض صفحات التقرير بشكل صحيح، لكن على بعض الأجهزة يمكن أن ينتهي الحفظ بملف PDF حجمه **0 بايت**، ثم عند الرجوع من شاشة الطباعة قد يعاد إنشاء WebView ويظهر تسجيل الدخول بدلاً من صفحة التطبيق السابقة.

## التغيير الجذري في مسار Android
- مسار الطباعة الأساسي لم يعد ينشئ WebView ثانياً لنسخة HTML كاملة من التقرير.
- يتم الآن تجهيز نسخة التقرير كعنصر طباعة فقط داخل **WebView الرئيسي الخاص بـ Capacitor**، خارج الشاشة في الوضع العادي ومرئي فقط في `@media print`.
- يتم إخفاء `#reportExportArea` القديم أثناء هذه العملية حتى لا يطبع التقرير مرتين.
- Native plugin يأخذ `getBridge().getWebView()` ثم يستخدم الواجهات العامة الرسمية: `createPrintDocumentAdapter()` ثم `PrintManager.print()`.
- يحتفظ plugin بمهمة `PrintJob` ويتابعها حتى `completed / cancelled / failed`، ولا يزيل مصدر التقرير فور فتح شاشة الطباعة.
- مسار HTML القديم بقي كمسار توافق احتياطي فقط.

هذا يقلل استهلاك الذاكرة وقت فتح Print Spooler ويمنع التخلص المبكر من مصدر الصفحات أثناء كتابة الملف النهائي.

## إصلاح الرجوع إلى صفحة تسجيل الدخول
قبل تسليم التحكم لشاشة الطباعة يقوم التطبيق بحفظ:
- هوية الحساب المحلية الموثقة الموجودة أصلاً في النظام.
- Snapshot البيانات.
- الصفحة الحالية.

وعند إعادة إنشاء واجهة التطبيق بعد الطباعة:
- يعطى Supabase وقتاً واقعياً لقراءة الجلسة مع Retry بدلاً من مهلة 500ms القديمة.
- إذا كانت العودة من الطباعة حديثة، تعرض نسخة التطبيق المحلية الموثقة مباشرة ثم تتحقق من جلسة Supabase في الخلفية.
- تعاد الصفحة السابقة، ومنها صفحة **التقارير**، بدلاً من الرجوع لتسجيل الدخول أو الصفحة الرئيسية.

## ما لم يتغير
- PDF ما يزال Vector عبر Chromium/WebView، وليس صورة html2canvas.
- Cairo وRTL وبنية الجداول وAuto-fit وإصلاح الصفحات البيضاء في v2.40.5 باقية.
- لا يوجد SQL migration لهذا الإصدار.
