# حلقتي v2.13.7 — إصلاح المزامنة بعد العمل دون إنترنت

## سبب المشكلة
عند فتح التطبيق وهو غير متصل كان التطبيق يستعيد هوية المستخدم والبيانات من النسخة المحلية حتى يستمر العمل. عند عودة الإنترنت كانت قائمة المزامنة قد تبدأ قبل أن تستعيد مكتبة Supabase جلسة JWT صالحة. وقتها يصل INSERT إلى `attendance_records` كطلب غير موثّق أو بجلسة منتهية، فتمنعه RLS برسالة `new row violates row-level security policy`.

## الإصلاح
- التحقق من جلسة Supabase قبل أي replay للقائمة المحلية.
- تجديد الجلسة تلقائياً عندما تكون منتهية أو قريبة الانتهاء.
- التحقق من المستخدم من الخادم عبر `getUser()` قبل الكتابة.
- عند RLS/Auth failure تتم محاولة refresh واحدة ثم إعادة نفس العملية مرة واحدة.
- إذا تعذر تجديد الجلسة تبقى كل العمليات المحلية في الطابور ولا يتم حذف أي شيء، ويظهر للمستخدم أن تسجيل الدخول مطلوب للمزامنة.
- الكتابات المباشرة للحضور والسلوك والجلسة والتقرير بعد رجوع الإنترنت تمر عبر نفس بوابة التحقق.
- فتح roster بعد رجوع الاتصال لا يستبدل البيانات المحلية إذا لم تعد جلسة الخادم جاهزة.
- لم يتم تخفيف RLS ولم يتم فتح صلاحيات قاعدة البيانات.
- محرك PDF العربي المستقر وبقية وظائف v2.13.4 لم تتغير.

## استعادة البيانات المعلقة من v2.13.4
ثبّت v2.13.7 فوق النسخة الحالية من دون حذف التطبيق. LocalStorage والطابور المحلي يبقيان كما هما. افتح التطبيق مع الإنترنت. ستتم محاولة تجديد الجلسة ثم مزامنة البيانات. إذا ظهرت عبارة `تسجيل الدخول للمزامنة` سجّل الدخول بالحساب نفسه ثم اضغط شارة المزامنة؛ العمليات المحفوظة ستبقى حتى نجاح الرفع.
