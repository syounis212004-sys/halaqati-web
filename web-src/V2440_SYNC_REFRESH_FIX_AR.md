# حلقتي v2.44.0 — إصلاح اعتماد ولي الأمر والتحديث والمزامنة

## إصلاح اعتماد ولي الأمر
- لم يعد التطبيق يعتمد على Snapshot قديم للحالة `pending` بعد اعتماد الحساب من المسؤول.
- زر **تحديث حالة الحساب** يقرأ الحالة من Supabase مباشرة عبر مسار التحديث الحالي.
- إذا كانت شاشة الانتظار مفتوحة، يعيد التطبيق التحقق تلقائياً كل 12 ثانية وعند عودة التطبيق للواجهة.
- عند انتقال الحساب إلى `approved + active` تُفتح لوحة ولي الأمر مباشرة دون الحاجة لتعديل الاسم أو تسجيل الخروج والدخول.

## السحب للتحديث
- إضافة Pull-to-Refresh داخل Android/Capacitor وPWA.
- عند السحب من أعلى الصفحة: يرفع الطابور المحلي أولاً، ثم يجلب أحدث بيانات الحساب والطلاب والجلسات والواجهة.
- مؤشر مرئي خفيف ومتوافق مع RTL وReduced Motion.

## تسريع Offline Sync
- تقليل فحص الجلسة على Supabase: كل session يتم التحقق منها مرة واحدة تقريباً في دورة المزامنة بدلاً من إعادة SELECT لكل حضور/سلوك/تسميع.
- فحص الجلسات الموجودة أصلاً يتم على دفعة ويُعاد استخدام نتيجته.
- إشعارات الحضور والسلوك والتقرير لم تعد تحجز مسار رفع البيانات؛ تعمل بطابور خلفي محدود إلى 3 مهام متزامنة.
- بنود التسميع داخل التقرير تُرفع بالتوازي ثم تتم معالجة الحذف بعد اكتمالها.
- لا تُكتب حالة `syncing` المؤقتة إلى كامل Outbox قبل كل عملية، لتقليل I/O على localStorage/IndexedDB.
- فحص الشبكة يستخدم نتيجة حديثة عند توفرها بدلاً من health request إجباري مع كل محاولة.
- بعد اكتمال الرفع يتم Core refresh سريع أولاً، بينما التحميل الثقيل يكمل في الخلفية من Performance Core.
- خفض فترة إعادة محاولة المزامنة التلقائية من 20 ثانية إلى 8 ثوانٍ.

## ملاحظة Supabase
Performance Advisor الحالي للمشروع ما زال يظهر تحذيرات RLS initialization وبعض foreign keys غير المفهرسة. هذه ليست السبب الوحيد لبطء المزامنة، ولم يتم تعديل RLS في هذه النسخة حتى لا تتغير الصلاحيات بدون Migration مدروس منفصل.
