# حلقاتي 2.40.5 — إصلاح PDF الفارغ في الطباعة المتجهية

## سبب العطل المؤكد

ملف PDF الفارغ الناتج من الهاتف ليس فشلًا في بيانات التقرير ولا في Chromium نفسه. الملف يحتوي صفحات A4 أفقية أنشأها Chromium/Skia، لكن بلا أي خط مضمن وبلا نص أو صور؛ أي أن هيكل الصفحات أُنشئ بينما محتوى التقرير لم يُرسم.

السبب في CSS القديم داخل التطبيق: عند وضع الطباعة توجد قاعدة تخفي كل عناصر `body` ثم تعيد إظهار `#reportExportArea` فقط. محرك PDF المتجهي الجديد لا يطبع `#reportExportArea`؛ بل ينسخ المعاينة إلى جذر مستقل اسمه `#hf-vector-print-root`. لذلك عند انتقال WebView إلى print media كانت القاعدة القديمة تجعل النسخة كلها `visibility:hidden !important`، فتخرج صفحات بيضاء صحيحة المقاس.

## الإصلاح

- إضافة override مخصص في آخر CSS المرسل لمحرك Chromium، بعد CSS التطبيق كله، يعيد إظهار `#hf-vector-print-root` وجميع أبنائه أثناء الطباعة فقط.
- إبقاء الإخفاء محصورًا في بقية واجهة التطبيق؛ لا يتم إظهار أي شاشة أو زر أو نافذة داخل PDF.
- الحفاظ على Vector PDF، Cairo، RTL، النص القابل للبحث، الاحتواء التلقائي للجداول، وفصل المسارات كما هي.
- لا تعديل على Supabase ولا SQL ولا بيانات الطلاب.
- رفع الإصدار إلى 2.40.5 / 24005 حتى يثبت Android التحديث فوق 2.40.4.
- إضافة فحص Regression جديد يمنع رجوع مشكلة الصفحات البيضاء إذا بقيت قاعدة الطباعة القديمة موجودة.

## اختبار مهم بعد بناء APK

1. افتح التقارير وجهّز شهر سبتمبر 2026.
2. افتح معاينة التقرير وتأكد أن البيانات ظاهرة.
3. اضغط تنزيل PDF، ثم اختر «حفظ بتنسيق PDF» من شاشة Android.
4. افتح الملف: يجب أن تظهر العناوين والجداول والطلاب بدل الصفحات البيضاء.
5. جرّب «جميع المسارات» ثم كل مسار منفصل.

لا توجد Migration لهذه النسخة.
