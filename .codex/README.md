# إنفاذ الجودة في Codex

يكتشف Codex أحداث `UserPromptSubmit` و`PreToolUse` و`PostToolUse` و`Stop` من `.codex/hooks.json` في المشروع الموثوق. يتطلب تنفيذ الأوامر Python 3.9 أو أحدث، وGit وبيئة POSIX. راجع المصادر عبر `/hooks` في Codex وثق بالتعريفات التي راجعتها. لكل جلسة ملف محلي في دليل Git باسم `halaqati-codex/`. يسجل بصمات الفروق والتقارير المختصرة وأوامر الفحوص. تجنب الأسرار في هذه التقارير. تبقى إعدادات Claude ومسار الموافقة على النشر مستقلين. [توثيق Codex الرسمي](https://developers.openai.com/codex/hooks)

## تسجيل أدلة العمل

نفّذ كل أمر من جذر المستودع في استدعاء Bash مستقل داخل Codex. تُسجَّل الشواهد عندما يرى `PostToolUse` الأمر ونتيجته.

- **الحركة**. طبّق المهارة ذات الصلة، ثم سجّل قرارًا مستندًا إلى الكود قبل تعديل تفاعل أو انتقال. تفحص البوابة رقع الحركة التي يمكن تمييزها، وتعيد فحص فرق الموقع عند الاعتماد والإكمال.
- **المراجعة**. طبّق Ponytail Review على الكود المتصل بالفرق وسجّل نتيجة المراجعة. يطلب الفاحص المراجعة عند تغيير 60 سطرًا في ملف واحد أو 150 سطرًا إجمالًا ضمن `web-src/` و`.ua/tools/` و`.codex/`.
- **التدقيق**. عند طلب تدقيق فعلي، سجّل نطاقه ونتيجته بعد تطبيق Ponytail Audit. يتعرّف الفاحص على صيغ الطلب المباشرة بالإنجليزية والعربية، ومنها `دقّق …` و`Audit …`، ويظل شرط استخدام المهارة قائمًا لأي تدقيق فعلي.
- **الاختبارات**. شغّل الفحص المناسب عبر `check --`. يسجَّل نجاح الأمر للفرق الذي خضع للفحص. فحص Git للتنسيق وحده غير كافٍ. أعد الفحص إذا تغيّر الفرق. جهّز الفهرس بـ`git add` في أمر منفصل، ثم اعتمد باستخدام `git commit -m`.

```sh
python3 .codex/enforce.py note motion accessible-animation 'تحققت من مسار الحركة المختصرة وحددت بديلًا يحافظ على وضوح حالة التركيز'
python3 .codex/enforce.py note review ponytail-review 'راجعت مسارات الاستدعاء والفشل وسجلت نتيجة المراجعة في التقرير'
python3 .codex/enforce.py note audit ponytail-audit 'فحصت النطاق المتفق عليه وسجلت النتائج وأجزاء السلوك غير المفحوصة'
python3 .codex/enforce.py check -- node --test .ua/tools/verify-graph.test.mjs
python3 .codex/enforce.py check -- python3 .codex/test_enforce.py
python3 .codex/enforce.py check -- npm --prefix web-src run check:legacy
```

اكتب وصف ما طبّقته في كل مهمة. ملاحظات المهارات إفادات عن العمل ويظل تقييم مضمونها جزءًا من المراجعة. قراءة `SKILL.md` أو ظهور المهارة في الفهرس لا ينشئان إفادة. يغطي منع الأوامر المبكر رقع `apply_patch` وأوامر `git commit` المباشرة التي يراها Codex. يغطي فحص الإكمال فرق Git في نطاق المهمة ويطلب متابعة واحدة قبل إظهار أي شرط بقي غير مستوفى. لا يعتمد الإنفاذ على Understand Anything أو `understand-diff`.

## الاختبارات المعزولة

شغّل `python3 .codex/test_enforce.py` لفحص الطلبات والسماح والمنع في مستودعات Git مؤقتة. شغّل `node --test .ua/tools/verify-graph.test.mjs` لاختبار V15. لإثبات الاكتشاف في نسخة Codex الحالية، افحص `/hooks` أو اطلب `hooks/list` عبر `codex app-server`. يظل تنفيذ Hooks مرتبطًا بثقة كل مستخدم في مشروعه وتعريفاته.
